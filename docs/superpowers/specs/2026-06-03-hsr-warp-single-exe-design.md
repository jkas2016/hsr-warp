# HSR 워프 트래커 단일 실행파일화 — 설계

작성일: 2026-06-03

## 목표

자가 호스팅 HSR 워프 추적기를 **단일 실행파일**로 만들어 사용 단계를 대폭 줄인다.
현재는 ① 게임에서 전언기록 열기 → ② PowerShell 스크립트를 경로 인자와 함께 실행 →
③ 생성된 HTML을 수동으로 열기, 3단계에 경로 수동 지정까지 필요하다.

개선 후 흐름: **exe 실행 → 브라우저 자동 오픈 → (경로 자동 채워짐) → "조회" 클릭 → 실시간 진행 → 차트 자동 표시.**

## 설계 기준 (우선순위)

1. **결과물이 가볍고 호환성이 좋을 것** — 런타임/DLL 의존 없는 정적 단일 바이너리.
2. 작업량(포팅 등)은 신경 쓰지 않는다. 단일 소스 원칙도 강제하지 않는다.

이 기준에 따라 Node SEA(50~80MB, Node 런타임 내장)는 탈락, **Go 정적 바이너리(~8MB)**를 채택.

## 아키텍처

```
hsr-warp.exe  (Go 정적 바이너리, 런타임 의존 없음, Win7~11 그대로 실행)
│
├─ 수집기      캐시 data_2 읽기 → authkey URL 정규식 추출 → getGachaLog 페이지네이션(증분)
├─ 저장        SRGF v1.0 JSON, 월별 분리(data/warp_YYYYMM.json) — 영향받은 월 파일만 병합·재작성(비파괴)
├─ HTTP 서버   localhost:<port> — 대시보드 + 데이터 API + SSE 진행 스트림
└─ 내장 자산   go:embed 로 dashboard.html + analyze.js 를 exe 안에 포함
                analyze.js 는 포팅 없이 브라우저에서 그대로 실행
```

분석 로직(50/50 픽뚫 판정 등)은 전부 브라우저의 `analyze.js`가 담당한다. Go는 **데이터 수집·저장·제공**만 한다.

### 컴포넌트 경계

- **collector** (Go): 게임 경로 → authkey URL → API 호출 → 정규화된 워프 레코드 목록. 외부 의존: HTTP, 파일시스템.
- **store** (Go): SRGF 병합/중복제거/월별 그룹핑/디스크 입출력. 외부 의존: 파일시스템.
- **server** (Go): HTTP 라우팅, SSE, 내장 자산 서빙, config 입출력.
- **dashboard** (브라우저): `analyze.js` + 렌더링. 입력은 `/api/data`의 SRGF JSON. 백엔드 내부 불변.

## HTTP 인터페이스

| 경로 | 역할 |
|------|------|
| `GET /` | 대시보드 HTML (내장 자산) |
| `GET /api/data` | 저장된 전체 SRGF JSON(합본) 반환 → 즉시 차트 렌더 |
| `GET /api/config` | 마지막 사용 게임 경로 반환 |
| `POST /api/config` | 게임 경로 저장 |
| `GET /api/detect` | HoYoPlay 흔한 설치 경로 자동탐지 결과 반환 |
| `GET /api/fetch?path=...` | **SSE 스트림**: 증분 조회 진행(`캐릭터 +20건...`) 푸시 → 완료 시 병합·월별 저장 후 최종 데이터 이벤트 |

## 데이터 흐름

1. exe 실행 → 빈 포트 선택(기본 8787, 충돌 시 다음 포트) → 기본 브라우저로 `localhost:<port>` 자동 오픈.
2. UI 로드 시 `/api/detect` + `/api/config`로 경로 입력란 자동 채움. `/api/data`로 기존 데이터가 있으면 즉시 차트 표시.
3. "조회" 클릭 → `GET /api/fetch?path=...` SSE 연결.
4. 서버: 캐시에서 authkey 추출 → 배너별(`1`,`2`,`11`,`12`) 증분 페이지네이션. 저장분보다 최신 id만 수집(저장분 id 도달 시 중단). 각 페이지마다 진행 이벤트 푸시.
5. 수집 종료 → **신규 레코드를 월(YYYYMM)별로 그룹핑 → 영향받은 월 파일만** 로드·병합·중복제거·정렬 후 재작성. 신규가 없는 월 파일은 손대지 않음(보존). → 디스크의 모든 월 파일을 읽어 합본 구성, 최종 데이터를 SSE로 전송.
6. UI: 진행 로그 실시간 표시 + **변경 요약**(배너별 신규 건수, 갱신된 월 목록) 표시, 최종 데이터 수신 시 `analyze.js`로 분석·차트 갱신.

## 저장 / 설정

- **월별 분리 유지 + 비파괴 부분 재작성**: `data/warp_YYYYMM.json` (SRGF v1.0). 이번 조회로 **신규 레코드가 생긴 월 파일만** 로드·병합(id 중복제거)·정렬 후 재작성한다. 신규가 없는 월 파일은 건드리지 않는다.
  - 현 PS 동작(전체 월 파일 삭제 후 재작성)은 **폐기**한다. authkey가 최근 기록만 줄 때 과거 월이 통째로 사라지는 위험을 없애기 위함.
  - 데이터 안전: 영향월 파일은 임시 파일에 쓴 뒤 원자적 교체(rename)로 갱신해 쓰다 만 파일이 남지 않게 한다.
- **config.json**: 마지막 게임 경로 저장. 사용자 머신 로컬 파일에만 기록(공유 config 아님 → 절대경로 금지 규칙과 무관).
- **큰 ID 정밀도**: Go에서 `math/big.Int` 또는 문자열 비교로 처리. `Number`/부동소수 비교 금지(현 `[decimal]`/`BigInt` 규칙 대응).
- **region → timezone 매핑**: 현 PS 로직 유지(asia=8, usa=-5, euro=1, cht=8, default=8).

## 도메인 상수 (외부 명세 종속, 변경 시 README 출처 따름)

- `gacha_type`: `11`=캐릭터, `12`=광추, `1`=일반(스텔라), `2`=출발.
- 50/50 픽뚫 판정 및 STANDARD 풀: `analyze.js` 안에 그대로 유지(브라우저에서 실행). HoYo가 표준 풀 변경 시 `analyze.js` 상단 `STANDARD` 배열만 수정.
- 형식·확률 출처: SRGF v1.0(uigf.org), Prydwen, StarRailRes.

## UI/UX — 데이터 비파괴 보장

불필요한 전량 삭제·데이터 손실이 실수로 일어나지 않도록 설계한다.

- **기본·유일 동작은 비파괴 증분 조회**. 메인 버튼은 "조회(신규만)" 하나. 디스크의 기존 데이터는 추가/병합만 되고, 영향받지 않은 월은 항상 보존된다.
- **전량 삭제 버튼은 두지 않는다.** 초기화가 꼭 필요하면 별도 보조 동작으로 분리하고, 명시적 확인(체크박스/타이핑 확인) + 갱신 전 자동 백업을 거치게 한다. 기본 화면에서는 노출하지 않는다.
- **조회 후 변경 요약 표시**: 배너별 신규 건수와 갱신된 월 목록(`2026-06 +5건` 등)을 보여줘 무엇이 바뀌었는지 명확히 한다. 신규 0건이면 "변경 없음"으로 안내(파일 미수정).
- **읽기 우선**: UI 진입 시 기존 데이터를 먼저 표시하므로, 조회하지 않아도 과거 기록을 항상 볼 수 있다. 조회 실패가 기존 표시를 지우지 않는다.

## 에러 처리

- authkey 없음 / 만료(retcode `-101`): SSE로 "게임에서 전언기록 화면을 최근 24시간 내 한 번 열고 다시 시도" 안내 이벤트 → UI 배너 표시.
- 게임 경로 틀림 / 캐시(data_2) 없음: 조회 시작 전 검증, 입력란 아래 에러 메시지.
- API 기타 retcode 오류: 메시지 그대로 SSE 에러 이벤트로 전달.
- 포트 충돌: 다음 포트 자동 시도.

## 테스트 계획 (테스트 코드 먼저)

프로덕션 코드보다 테스트를 먼저 작성한다.

- **collector**: authkey 정규식 추출(샘플 바이너리 텍스트), mock HTTP 서버로 페이지네이션·증분 중단·retcode 분기(-101 포함) 검증.
- **store**: SRGF 병합/중복제거(id 기준)/월별 그룹핑, **영향받은 월 파일만 재작성·미영향 월 파일 보존**(핵심), 신규 0건 시 파일 미변경, 원자적 교체, 큰 ID 문자열·big.Int 비교 검증. authkey가 최근 기록만 줄 때 과거 월이 보존되는 시나리오 포함. `sim_incremental.js`의 시나리오를 Go 테스트로 이식.
- **analyze.js**: 기존 `analyze.test.js` 그대로 유지(브라우저 분석 로직 불변).
- 테스트는 `go test ./...`로 일괄 실행.

## 폐기

- `Get-HSRWarp.ps1`, `Update-HSRDashboard.ps1` — Go 수집기로 대체.
- `Register-Schedule.ps1` (매달 자동 실행) — 라이브 UI 모델과 안 맞아 폐기(사용자 승인).
- `sim_incremental.js` — Go 테스트로 대체.
- `dashboard.template.html`의 마커 주입 방식(`/*__ANALYZE_JS__*/`, `/*__DATA__*/ null`) — 자산은 `go:embed`로 내장, 데이터는 `/api/data`로 동적 제공.

## 유지

- `analyze.js`, `analyze.test.js` (브라우저 분석 단일 소스).
- SRGF v1.0 저장 형식, 월별 분리.
- `gen_sample.js`(합성 데이터 수동 확인용)는 선택적 유지.
