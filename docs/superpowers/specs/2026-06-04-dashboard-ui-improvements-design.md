# 대시보드 UI 개선 설계 (이슈 #4)

> 출처 이슈: https://github.com/jkas2016/hsr-warp/issues/4
> 작성일: 2026-06-04

## 목표

`web/dashboard.html` 화면을 세 가지로 다듬는다.

1. **5★ 획득 기록(최신순) 페이징** — 기록이 누적되면 한 화면에 다 쏟아진다. "더보기" 추가.
2. **월별 집계 페이징** — 월이 쌓일수록 행이 길어진다. "더보기" 추가.
3. **'출발 워프' 배너 카드 숨김** — 1회성 초보자 배너(`gacha_type 2`, `kind: beginner`)라 배너별 현황 카드에서 통계 가치가 낮다.

## 범위와 불변식

- 변경은 **`web/dashboard.html` 한 파일**로 한정한다.
- **`web/analyze.js`는 변경하지 않는다.** 출발 배너를 데이터에서 제거하지 않고 렌더에서만 숨기며(아래 "출발 제외 범위"), 페이징은 순수 클라이언트 표시 로직이다.
- 따라서 `web/analyze.test.js`는 영향이 없어야 한다 — 회귀 통과만 확인한다.
- 분석 단일 소스(`analyze.js`)·비파괴 저장·BigInt ID 등 도메인 불변식은 이 작업과 무관하며 건드리지 않는다.

## 출발(beginner) 제외 범위 — "배너 카드만 숨김"

`analyze.js`의 `ORDER=['11','12','1','2']`로 출발(`'2'`) 배너는 `banners`·`all5`에 포함되고, `monthly()`·총계(`total`/`jade`/`count5`)는 list 전체(출발 포함)를 집계한다.

이번 작업은 **데이터는 그대로 두고 배너별 현황 카드에서만 출발 카드를 숨긴다.** 결과:

- 배너별 현황: 출발 카드 미표시.
- 5★ 획득 기록 테이블: 출발 보장 5★가 `'출발'` 태그로 **계속 표시됨**.
- 월별 집계 / 총 뽑기 / 소비 성옥: 출발 50연이 **그대로 포함됨**.

(대안인 "analyze 출력에서 완전 제외"는 총 뽑기·성옥 숫자가 출발 50연만큼 줄어 일관적이지만, 이번에는 선택하지 않는다.)

## 변경 상세

### A. 출발 배너 카드 숨김

배너 카드 루프(`dashboard.html:205`)에서 출발만 건너뛴다.

```js
for(const b of A.banners){ if(b.type==='2') continue; /* ...기존 카드 렌더... */ }
```

1줄 가드 추가. `analyze.js` 무변경.

### B. "더보기" 페이징 (5★ 기록 · 월별 집계)

현재 `render(A)`는 `app.innerHTML`을 통째로 다시 그린다. 더보기는 **해당 테이블 `tbody`만 부분 갱신**한다.

구조:

- 5★ 기록·월별 집계의 행 생성을 각각 작은 함수로 분리한다.
  - `fivesRows(A, limit)` → `A.all5.slice(0, limit)`의 `<tr>` 문자열.
  - `monthlyRows(A, limit)` → `[...A.monthly].reverse().slice(0, limit)`의 `<tr>` 문자열.
- 각 섹션 마크업에 `<tbody id="fivesBody">` / `<tbody id="monthBody">`와 그 아래 `<button id="moreFives">` / `<button id="moreMonth">`를 둔다.
- 표시 개수를 모듈 변수 `fivesShown`, `monthShown`으로 관리한다. `render()` 진입 시 초기값으로 **리셋**(재조회 후에도 처음부터 보이게).
- 더보기 클릭 → 표시 개수 `+= PAGE` → 해당 `tbody.innerHTML`과 버튼 라벨만 갱신. 남은 개수가 0이면 버튼을 숨긴다(`display:none`).
- 버튼 라벨: `더보기 (N개 남음)` (월별은 `더보기 (N개월 남음)`).
- 이벤트 바인딩: `render()`가 매번 `app.innerHTML`을 덮어쓰므로 `app.innerHTML` 설정 직후 `addEventListener`로 바인딩한다(인라인 `onclick` 미사용 — 기존 코드 스타일 일치).

초기 표시 개수 / 페이지 크기:

| 테이블 | 초기 | 더보기당 |
|---|---|---|
| 5★ 획득 기록 | 20 | +20 |
| 월별 집계 | 12 | +12 |

`A.all5` 또는 월별 길이가 초기값 이하이면 더보기 버튼을 처음부터 숨긴다.

## 테스트 / 검증 계획

테스트 계획을 먼저 정하고 구현한다.

1. **회귀 — analyze 단위 테스트**: `node web/analyze.test.js`가 그대로 통과해야 한다(`analyze.js` 무변경이므로 깨지면 안 됨). `go test ./...`도 무관하게 통과 유지.
2. **렌더 자동 검증 (chrome-devtools-mcp)**: 빌드한 exe(또는 로컬 서버)를 띄우고 대시보드를 열어 확인한다.
   - 배너별 현황에 **출발 카드가 없다** (캐릭터/광추/일반만).
   - 5★ 기록 테이블에 초기 **20행 이하**가 보이고, 데이터가 더 많으면 "더보기" 버튼이 있다.
   - 더보기 클릭 시 행이 추가되고, 끝에 도달하면 버튼이 사라진다.
   - 월별 집계도 동일(초기 12행, 더보기 동작).
   - 콘솔 에러 없음.
3. 페이징 로직을 별도 순수 함수+단위 테스트로 분리하는 것은 이 규모엔 과하다(YAGNI). 표시 개수 슬라이싱뿐이라 회귀 위험이 낮고, 위 렌더 검증으로 충분하다.

## 영향 없는 것 (명시)

- `analyze.js` / `analyze.test.js` 로직.
- 50/50 판정, 월별 버킷팅, 총계 계산.
- Go 백엔드(`internal/**`, `main.go`).
- 다른 차트(희귀도·천장·50/50·월별 뽑기)는 그대로.
